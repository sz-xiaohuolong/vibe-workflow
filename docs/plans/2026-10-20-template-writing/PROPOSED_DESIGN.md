## 1. 背景与设计目标

### 1.1 技术现状与问题

[当前技术设计第 2、3 节](TECH_DESIGN.md#2-技术栈与工程结构)说明了实际资源组织：`SKILL.md` 负责路由，`references/` 负责详细规则，`assets/templates/` 提供模板，指南和示例解释用法，Bash 脚本安装和校验。五模板、PRD 默认名称、旧 SPEC 兼容说明已在当前文件中出现，但快照元数据写明本轮修改尚未提交且不含运行结果。

需要解决的是写作契约能否从入口连续传递到正文和验收：模板必须可填写，摘要不能替代详细规则，设计与事实不能混写，专业章节不能扩大范围。脚本的文件和关键词检查只能保护部分结构，无法证明 Agent 真实写作行为。这个证据边界必须保留。

## 3. 总体架构与核心流程

### 3.1 组件边界与交互

| 组件 | 本次职责与变化 | 输入与输出 | 依赖及信任边界 |
|---|---|---|---|
| 文档入口选择 | 先定位现有职责，再选择对应模板 | 用户批准范围、真实地图 → 实际 owner 路径 | 项目事实优先于模板建议目录 |
| 写作规范与模板 | 将适用契约组织成可填写正文 | 已确认需求及事实 → 概要、PRD、方案、现状和任务 | 模板示例不是已确认业务规则 |
| 文档维护 Agent | 在本次授权内填写和同步 | 项目事实、模板 → 文件变化及明确未知 | 只有一个执行 owner；不自动扩大权限或启动下一阶段 |
| 检查与结果记录 | 区分预期与真实证据 | 拟检查输入 → 实际结果及覆盖限制 | 计划只定义方法，实际结果由既有验证记录拥有 |
| 安装及适配入口 | 让分发后的 Skill 仍可访问一致资源 | 源 Skill 或适配正文 → 目标宿主入口 | 安装属于外部写入；本次不执行 |

该架构是 Agent 读取文件并遵守对话协议，没有新增后台进程或执行引擎。

### 3.2 读写路径与状态传播

1. Agent 读取用户范围、实际项目规则和唯一职责地图，确认本次需要修改的 owner；已有等价文件直接沿用。
2. 按该文档用途读取模板及 `document-quality.md` 对应部分，先列真实适用契约，再填写正文。
3. PRD 前三章分别写摘要并链接概要；详细需求使用 REQ/AC，方案及任务精确引用，不复制完整背景和结果表。
4. 实施后按真实检查结果更新进度/验证 owner；只有成立并有依据的当前事实进入 TECH_DESIGN。结果仍为未核验时不推进验证或发布状态。
5. 发现来源冲突、缺失事实或依赖不可用时保留用户内容和可恢复文件，说明影响及下一步，不借默认值或示例补齐。

此流程没有新增状态。`SPECIFIED`、`UNVERIFIED`、`IMPLEMENTED_UNVERIFIED`、`VERIFIED` 等沿现有规范使用。命名改变不触发状态转换；文件写入不自动变为已验证。

### 3.3 影响范围

| 模块或系统 | 影响内容 | 核查依据与结论 |
|---|---|---|
| 五模板及写作规范 | 直接决定正文结构与填写规则 | 文件已读取；当前内容见 TECH_DESIGN，实际可用性待检查 |

| 安装器 | 原生安装复制整个 Skill；Cursor 使用独立内嵌文本 | `install.sh`；应先核对本次契约是否需要同步，不能假设单独适配文件会自动进入 Cursor 生成结果 |

## 4. 详细设计

### 4.1 文档结构与兼容数据

本次持久化对象为仓库文件，不新增数据库 Schema、查询索引或缓存。需要维持的结构契约如下：

| 对象或字段 | 类型或格式 | 默认值与约束 | 写入方与读取用途 |
|---|---|---|---|
| 需求 owner 路径 | 仓库相对路径 | 新建默认 `PRD.md`；已有 SPEC/等价路径不变；仅一份 owner | Agent 按地图定位，恢复和验证读取实际路径 |
| Requirement Version/Status | 既有需求控制字段 | 版本来源真实；模板保持草稿，已有明确批准后才冻结 | 概要拥有基线，PRD 引用同一基线 |
| REQ/AC/Task 标识 | 既有项目编号 | 保留原编号，不平行新建 FEAT 或重编号 | PRD、设计、计划及结果记录互相追溯 |
| 方案状态 | 既有 `PROPOSED/APPROVED/IMPLEMENTED/REJECTED` | 状态对应事实；批准不等于实现验证 | 方案拥有选择历史，当前设计只接收成立部分 |
| 事实依据 | 路径、符号、配置或真实结果定位 | 区分文件存在、已执行和未核验；不引入虚构结果 | 当前设计和交付说明定位可追溯来源 |
| 文档链接 | 现有 Markdown 相对引用 | 引用真实路径；章节引用准确；避免复制另一份事实表 | 用户、Agent 和现有链接校验读取 |

迁移策略为“不迁移存量 owner”。对活跃默认引用逐处判断；旧 SPEC 兼容说明和历史引用保持。目标目录没有现有需求职责才创建 PRD。恢复依赖原文件及实施前保存的工作树差异；base commit 不能单独恢复本轮尚未提交修改。

### 4.2 文档接口契约

**模板选择接口。** 调用方为读取 Skill 的 Agent；输入是文档职责、当前项目实际路径及已确认范围。输出是沿用的 owner 和对应模板结构。无该职责且已授权新建时使用默认名称；发现多个 owner 冲突则返回明确分歧及受影响范围，不能写入第二份需求来掩盖冲突。

**PRD 写作接口。** 输入为概要基线、已确认行为及既有编号；输出为九章正文。前三章摘要可独立理解，分别精确引用概要；第五章每项核心功能写前提、正常流程、输入与规则、适用权限、异常恢复和给定—当—则 AC。接口不接受“模板示例即默认规则”的推断；行为缺口进入待决问题。

**方案与现状接口。** 方案输入是现状依据和目标要求，输出是选择、理由、详细契约、影响及验证恢复设计。当前技术设计只接收已经实现且有代码、配置或运行证据依据的事实；输出同时标明依据层级和未知。静态文件可支持“内容存在”，不能支持“命令运行成功”。

**计划接口。** 输入为 REQ/AC、目标设计和现状边界；输出为依赖图、文件映射、任务步骤、验证预期与恢复依据。实际完成状态和结果转交对应进度/验证 owner，计划只链接，不维护第二套状态。

| 错误条件 | 对调用方可见结果 | 文件及后续处理 |
|---|---|---|
| 来源不存在或不能定位 | 具体缺口、受影响契约和下一定位步骤 | 不编造路径，不把未知填成事实；不依赖缺口的正文可继续 |
| 产品行为未确认 | 明确待决问题及受影响 REQ/AC | 保留已确认范围，不能自行扩充冻结含义 |
| 专业章节不适用 | 必要时说明不适用原因 | 删除空表和无关章节，不新增组件填表 |
| 校验依赖缺失或未执行 | 记录未执行、缺失依赖及覆盖限制 | 不写 PASS/VERIFIED；实际证据留给后续记录 |
| 源文件与文档结论冲突 | 指出事实 owner、差异和影响 | 先修正对应事实或走已有变更 Gate，不静默抹平 |

### 4.3 核心逻辑与复杂边界

适用判断以真实影响为依据：有界面才展开四种界面状态，有数据或接口变化才给字段和输入输出，实际跨模块才建立接缝索引。数字来自已确认需求或测量来源，没有依据时只写可观察判据或未知。

本次没有新增并发、事务、幂等或自动重试机制。重复执行文档同步时只补可确认缺口，保留人工内容和历史，不重复追加模板正文。编辑中断时保留已写内容及差异，恢复先确认基线；不自动重置整个工作树。

## 5. 关键选择与依据

复用现有 Skill 的主入口、reference、模板和示例结构：模板承载正文骨架，reference 解释适用条件，现有脚本保护资源及引用契约。这样能直接支持可填写文档，同时避免新增生成器或运行依赖；代价是需要同步维护模板、规范和公开入口。

默认使用 PRD、沿用旧 SPEC 入口，以及分开记录目标方案与当前事实，均已由用户确认，直接作为设计约束。本次没有需要比较的实质技术备选，不将已排除的范围列为候选。普通实现理由保留在本节，无需新增 DEC。

## 6. 安全、隐私与可观测性

模板不增加鉴权或外部数据访问。实际写入继续受用户授权范围和项目规则限制；不要在模板示例或实际文档中填入真实密钥、敏感原文或无关人员数据。

本次不新增日志、遥测、指标和告警系统。运行定位仍依赖已有脚本的标准输出、退出结果和真实验证记录，记录被测输入、环境、范围及限制即可。脚本含有的成功字符串是实现文本，不是本次结果。没有依据设定告警阈值，也没有计划采集行为统计。
