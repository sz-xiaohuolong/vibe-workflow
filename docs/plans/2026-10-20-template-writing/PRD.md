本文件描述本仓库文档模板与命名优化应提供的行为。下列 REQ/AC 是本组文档内的需求追溯标识，不据此重编号其他项目的既有标识；开发状态和实际检查结果由对应进度与验证记录维护。

## 1. 产品概述与背景

使用 Vibe Workflow 的 Agent 需要将已确认的项目意图写成需求、方案、当前事实和任务。只有摘要或宽泛说明时，文档可能遗漏验收分支、技术契约或实施入口；混用 PRD 与 SPEC 还可能产生两份需求事实源。本次通过可填写模板和一致的命名兼容规则，使文档既能帮助人理解，也能支持 Agent 执行。

本次成功意味着五模板具备各自完整的写作骨架，PRD 独立可读、规则可验收，新旧项目可以沿唯一入口恢复。当前快照已有相关内容，是否满足全部验收仍需后续检查。

基线来源：[需求概要第 1 节](PROJECT_BRIEF.md#1-背景与产品定位)及[第 5 节 GOAL-001～005](PROJECT_BRIEF.md#5-成功指标与验收目标acceptance-goals)。

## 2. 目标与非目标

核心目标是让 Agent 直接按模板完成适用的正文契约，并使读者分清产品意图、目标方案、已核验现状、实施安排和真实结果。PRD 前三章摘要应足以独立理解本次工作，引用用于追溯，不能代替正文。

本次覆盖五模板、默认 PRD 名称、存量 SPEC 兼容、活跃引用及指南示例校验同步。它不增加新的业务能力、服务或持久化机制，不迁移历史文档，也不改动需求标识、状态机或已有发布历史。本次快照任务只交付五份文档；源码编辑、检查和远程同步属于后续计划。

基线来源：[需求概要第 3 节](PROJECT_BRIEF.md#3-目标与范围)，对应 GOAL-001～005。

## 3. 目标用户与使用场景

| 用户角色 | 角色特征与权限范围 | 核心诉求 | 典型触发场景与预期结果 |
|---|---|---|---|
| Agent | 按用户授权读取并修改项目，不能替用户新增产品承诺 | 从标准模板得到正文结构和填写要求 | 新建或实质修改文档时，先读取模板，再写可追溯的真实内容 |
| 开发者及需求确认者 | 阅读文档、决定产品范围和重大风险 | 单独读 PRD 就能理解本次目的，并找到具体验收和理由 | 审阅时能够定位背景、功能规则、方案及未核验项 |
| Skill 维护者 | 调整 Skill 资源及公开使用入口 | 新建用 PRD，旧项目恢复不受破坏 | 更新模板及指南后，活跃入口一致，历史仍可按原路径阅读 |

场景主线为“确认已有范围 → 找到现有 owner → 读取对应模板 → 按适用条件填写 → 定位验证入口 → 在真实进度/验证记录保存结果”。已有 SPEC 的场景在定位 owner 后继续写该文件；没有该职责时才新建 PRD。简单任务可以裁剪，五模板的存在不触发整套文档生成。

基线来源：[需求概要第 2 节](PROJECT_BRIEF.md#2-目标用户与核心场景)。

## 5. 核心功能详细规格与验收标准

### 5.1 REQ-001：五份可填写标准模板

**来源与前提。** 对应 GOAL-001。Agent 从 Skill 主入口、写作规范或用户指南进入 `skills/vibe-workflow/assets/templates/`。只有新建或实质修改相关文档才读取对应模板；用户已授权文档职责或项目确有缺失时才创建文件。

**正常流程。** Agent 先确定项目已有 owner 和适用范围，读取对应模板，再依据项目事实填写正文、删除填写提示与未替换占位，最后保留必要未知及精确引用。模板必须提供下列可见结构：

| 模板 | 必须能直接填写的内容 | 职责边界 |
|---|---|---|
| `PROJECT_BRIEF.md` | 需求控制、背景定位、用户场景、目标范围、总体约束、成功目标、待决问题 | 保存意图和确认基线；不复制逐功能 AC 或实现方案 |
| `PRD.md` | 本文件第 5.2 节的九章及详细功能规格字段 | 保存完整有效行为；不维护实现进度 |
| `PROPOSED_DESIGN.md` | 现状与目标、技术栈工程约定、架构流程、适用详细契约、选择理由、安全观测、风险与验证恢复 | 保存目标方案；批准不能等同实现 |
| `TECH_DESIGN.md` | 当前边界、栈和组件、真实读写路径、数据接口、错误恢复、安全观察、运行验证入口、缺口 | 每项现状能定位到代码、配置或真实证据 |
| `IMPLEMENTATION_PLAN.md` | 前置环境、文件映射、任务依赖、具体步骤、验收矩阵、交付恢复、里程碑与偏差入口 | 保存预期安排；实际结果引用对应记录 |

**规则与权限。** 标题、字段和表格应直接出现在模板正文中，不能仅藏在注释或外部规范。模板中的填写提示不作为项目事实；读取和写入权限继续由用户和项目规则决定，模板不授予新增副作用。

**异常与边界。** 找到等价 owner 时在原文件渐进完善，不复制第二份；依据不足时写明待澄清或未核验及影响，不填入虚构字段、负责人或通过结果。简单任务可以合并短节，但适用的实施和验收信息仍可定位。

| 验收编号 | 可判定场景 | 输入与观察入口 |
|---|---|---|
| AC-001 | 给定已批准的文档写作范围，当 Agent 读取五模板，则每个模板均包含上表对应的正文结构及可填写字段，可直接承载该职责的信息。 | 五模板文件；写作规范“模板与职责”；后续静态审阅 |
| AC-002 | 给定项目已有等价 owner 或事实缺口，当 Agent 按模板写作，则沿用原入口、清理未替换提示，未知明确可见，不为补表创建重复 owner 或虚构事实。 | Skill、init/artifacts 规则与实际生成文档；本次不执行行为检查 |

### 5.2 REQ-002：PRD 九章与独立摘要

**来源与前提。** 对应 GOAL-002。使用者是生成和阅读已确认范围 PRD 的 Agent 与开发者，入口为 PRD 模板和当前项目需求 owner。输入是已经确认的范围、规则及现有事实，不从模板示例补定产品含义。

**正常流程。** 先写背景、目标和用户摘要；各摘要之后引用 BRIEF 的对应章节；再按需求编号展开优先级与详细规格；最后说明适用交互、约束边界、埋点及待决风险。

| 顺序 | 标准章 | 可观察要求 |
|---|---|---|
| 1 | 产品概述与背景 | 可独立理解的问题、定位和成功定义，引用概要背景与目标 |
| 2 | 目标与非目标 | 可独立理解的本次承诺及排除范围，引用概要范围 |
| 3 | 目标用户与使用场景 | 用户、权限边界及场景摘要，引用概要用户章节 |
| 4 | 功能需求与优先级 | 以 REQ 为唯一需求编号，说明优先级口径及详细规格入口 |
| 5 | 核心功能详细规格与验收标准 | 前提、主流程、输入规则、适用权限、异常恢复、关联 AC 与检查入口 |
| 6 | 交互与界面设计要求 | 有界面时核对空、加载、错误、极限状态；无界面说明原因 |
| 7 | 限制条件、非功能需求与边界场景 | 已确认约束、口径、验证方式及适用跨功能边界 |
| 8 | 埋点与数据统计需求 | 有已确认采集需求才列事件、触发、属性、目的与限制 |
| 9 | 待决问题与风险登记 | 记录影响行为的未知、受影响验收、闭环条件及实际风险 |

**规则与异常。** 核心功能 AC 使用“给定—当—则”，能从输入和观察位置判定。单一同步操作无需独立状态机；真实异步生命周期或跨系统验收才增加状态表或测试接缝索引。未知且会改变用户可见结果的规则进入第 9 章，不借 `FROZEN` 自行补定。前三章不能只写“见概要”，也不复制整份概要。

| 验收编号 | 可判定场景 | 输入与观察入口 |
|---|---|---|
| AC-003 | 给定需要展开标准 PRD 的任务，当使用新模板，则九章按上表组织，前三章各有独立摘要，并分别引用概要背景、范围和用户章节。 | `assets/templates/PRD.md`、写作规范及指南中的结构说明 |
| AC-004 | 给定已确认正常规则及异常边界，当填写核心功能，则读者能找到前提、流程、输入校验、适用权限、异常恢复以及关联 REQ 的可观察 AC；未知产品规则进入待决问题。 | PRD 模板第 5、9 章及实际文档正文；按需求追溯审阅 |

### 5.3 REQ-003：PRD 默认命名与旧 SPEC 兼容

**来源与前提。** 对应 GOAL-003。入口为新建、接管和恢复项目的对话协议、Document Map 及模板引用。使用者能读取项目实际规则和已有需求文件；本功能不增加权限机制。

**正常流程。** 先找当前项目采用的需求 owner；已采用 SPEC 或等价路径则沿用；不存在该职责且确需新建时才使用 `PRD.md`，标题为“产品需求文档（PRD）”。唯一地图登记真实路径，后续按登记读取。

**规则与异常。** `SPECIFIED` 仍是原工作流机器状态，REQ/AC 和已有 Task 编号不改变。历史正文中的 SPEC 不作全库替换。存在多个相互矛盾的需求 owner 且无法判断时保留现场并说明冲突，不猜选、不合并为新 PRD。此时可继续不依赖该冲突的工作。

| 验收编号 | 可判定场景 | 输入与观察入口 |
|---|---|---|
| AC-005 | 给定没有既有等价需求 owner 且已授权创建需求文档，当 Agent 创建文档，则使用 `PRD.md` 及中文 PRD 标题，活跃默认引用指向该名称。 | 主入口、artifacts/init、PRD 模板、地图/项目模板、指南和适配器 |
| AC-006 | 给定项目唯一需求 owner 为 `SPEC.md` 或已登记的等价路径，当 Agent 恢复或修改需求，则继续读取和更新该文件，不迁移、不复制第二份 PRD。 | 入口定位协议与实际目录差异；后续受控观察 |
| AC-007 | 给定已有 REQ/AC、Task、机器状态及封存历史，当同步命名引用，则这些标识和历史内容保持原貌；多个 owner 冲突会被显式报告。 | 活跃引用与拟提交差异、lifecycle 规则；不读取无关历史正文 |

### 5.4 REQ-004：事实职责与可执行任务

**来源与前提。** 对应 GOAL-004。Agent 根据文档用途选择事实 owner，来源是现有代码、配置、用户决定及真实运行证据。用户读取文档时应能区分已批准、已实现、已核验和待执行。

**正常流程。** 在方案设计引用当前相关事实，再写目标和理由；当前技术设计仅写已实现且有依据的事实并标明核验层级；计划按依赖列出小步交付，并将验证预期连接至 AC。实际状态和证据只记录在适用的 PROGRESS/VERIFICATION 或项目等价 owner。

**规则与异常。** 方案正文应展开适用字段和接口契约，任务必须包含编号、交付、依赖、文件、具体步骤、验证入口及预期、恢复依据。仅配置了命令时写“入口存在，未执行”，不能写通过。没有有效命令时先安排定位或写真实操作方式，不编造测试路径。未核验事实保持缺口，不因方案获批就同步为当前能力。

| 验收编号 | 可判定场景 | 输入与观察入口 |
|---|---|---|
| AC-008 | 给定同一功能的目标方案及当前文件，当生成两份设计，则方案写变化与理由，当前技术设计的事实有文件/配置/证据定位，并区分静态可见与运行已验证。 | PROPOSED_DESIGN、TECH_DESIGN 模板与正文 |
| AC-009 | 给定需要实施的需求，当编写计划，则每个任务具备交付、关联 REQ/AC、依赖、文件、步骤、验证预期及恢复依据；实际进度和检查结果引用对应记录。 | IMPLEMENTATION_PLAN 模板、进度/验证模板职责；计划第 3、4 节 |

### 5.5 REQ-005：专业内容按适用条件展开

**来源与前提。** 对应 GOAL-001、004。输入为真实项目是否涉及界面、数据、接口、并发、观测或发布等影响。模板提供提问与契约字段，不替用户决定产品范围。

**正常流程。** 先判断适用性；适用内容进入正文并给足实施和验收细节；不适用内容说明原因或按规范删除。示例只解释写法，实际项目使用自己的文件、规则和证据。

**规则与异常。** 不因表格出现就默认新增数据库、缓存、队列、重试、灰度或分析平台。性能、容量、覆盖率、工期、告警阈值和灰度比例须有已确认依据。缺少数字且不影响范围时使用可观察判据；影响行为或验收的未知进入待决问题。不存在界面时不造页面状态，不存在异步生命周期时不造状态机。

| 验收编号 | 可判定场景 | 输入与观察入口 |
|---|---|---|
| AC-010 | 给定无界面、无存储、无采集的文档任务，当按模板填写，则不凭空产生页面、数据表、缓存、埋点或自动重试，正文能解释会影响理解的省略。 | 写作规范“结构裁剪与适用条件”、五模板及本任务正文 |
| AC-011 | 给定输入未约定性能、容量、覆盖率、工期或告警数字，当填写设计和计划，则不套用示例数字；未知、量化依据和示例性质清楚可见。 | 五模板、指南和示例的说明；实际文档审阅 |

### 5.6 REQ-006：活跃入口、指南、示例与校验同步

**来源与前提。** 对应 GOAL-005。维护者在本仓库修改适用活跃文件，先确定哪些是公开规范、使用入口或校验资源，哪些是历史输出。当前快照没有本轮运行结果。

**正常流程。** 以模板和 reference 的职责为基准，同步 Skill 主入口、活跃引用、指南、README、适配入口与检查资源；示例明确是虚构写法片段，不能替代完整模板或真实项目证据；最后运行适用检查并将实际结果写入对应记录。该最后步骤是后续实施要求，本次没有执行。

**规则与异常。** 只改本次契约涉及的内容，保留历史输出。静态校验可以保护文件、元数据、链接和结构，不能单独证明 Agent 实际遵守行为。校验依赖或场景资源缺失时报告具体缺口，不安装未经本次允许的依赖，也不把跳过写为通过。已有提交推送授权只覆盖原任务明确的当前分支同步，不隐含发版或 PR。

| 验收编号 | 可判定场景 | 输入与观察入口 |
|---|---|---|
| AC-012 | 给定模板与命名契约变化，当同步活跃入口，则 Skill、reference、指南、README、适配器及适用模板引用表达同一规则，历史输出不进入改写范围。 | 实施计划第 2 节文件映射与后续拟提交差异 |
| AC-013 | 给定维护示例和校验资源，当完成同步，则示例保留虚构性质说明，校验定位 PRD 等必需资源；结果能区分静态结构和真实行为覆盖。 | `assets/examples/document-quality.md` 与 `tests/validate_skill.sh`；实际结果另记 |
| AC-014 | 给定检查未执行或依赖不齐，当交付文档或同步分支，则报告真实缺口，不宣称已通过、`VERIFIED`、`READY_TO_SHIP` 或已发布。 | 进度/验证 owner 和交付说明；本次明确为未执行 |
