# 文档质量优化实施计划

先保留现有输出，再调整规则和模板，最后比较实际效果。每一步都围绕 [需求分析及验收条件](SPEC.md)推进；具体设计见 [方案设计](PROPOSED_DESIGN.md)，执行状态统一维护在 [进度](PROGRESS.md)。

用户已确认方案并授权实施下列 T1–T5。本计划不指定版本号，不包含提交、发布或批量迁移。

## 任务顺序与交付

依赖关系：T1 → T2 → T3 → T4 → T5。前置任务的适用检查完成后才推进；独立样例在各自目录验证，生产规则由同一执行者修改。

| 任务 | 交付与修改范围 | 验收与关联需求 |
|---|---|---|
| T1：固定场景与基线 | 在 `tests/` 补文档质量场景和必要输入；按贡献规范在 `tests/scenarios.md` 登记新边界，保留旧规则的原始输出 | 三种复杂度、四类适用文档、关键事实清单齐全；AC-03、AC-04、AC-07 |
| T2：编写规范与示例 | 新增拟议的 `references/document-quality.md` 和 `assets/examples/document-quality.md`；四类各提供正例、反例和修改理由 | 通用规则、必要信息和可选章节触发条件可执行；AC-01、AC-02、AC-03、AC-04 |
| T3：接入入口与模板 | 更新 `SKILL.md`、`references/artifacts.md`、四类试点模板；仅在出现实际冲突时同步相关执行规则和静态断言 | 自动按需读取，局部更新保持局部，工程契约仍在；AC-02、AC-04、AC-05、AC-06 |
| T4：对照生成与检查 | 对固定输入生成候选输出，将对比与实际结果保存在 `tests/results/`；修正已定位的缺陷 | 逐项检查 AC-01–AC-07 的客观部分；运行相关静态校验，保留失败与重验依据 |
| T5：用户体验验收与收尾 | 呈现有代表性的前后文档及差异，记录用户反馈与适用范围；更新本任务进度及必要说明 | 用户确认阅读体验改善，客观缺陷已处理；未满足项如实记录，不自动扩展模板范围 |

每次改动前核对工作树，只保留本次任务的可恢复差异；基线提交仅用于比较，不等同于已经验证的稳定版本。失败时局部修正或恢复本任务改动，保留用户工作及有效证据。

## 对照场景

以下是测试场景方向，不是实际业务项目的新需求。T1 将完整输入固定后，两组共用，不在生成过程中补给某一组额外事实。

| 复杂度 | 输入情境 | 主要观察点 |
|---|---|---|
| 简单 | 已有项目仅修改列表空状态文案，更新已有相关记录 | 是否只修改必要内容，省略无关章节，不新建四份文档，不重写无关段落 |
| 中等 | 增加本地列表搜索，给定范围与主要过滤行为，但未定义具体匹配关系 | 需求、方案、顺序和当前状态是否容易理解；同一事实是否只维护一处；未定义规则是否保持待澄清 |
| 复杂 | 后台上传涉及排队、取消、重试和跨界面状态同步，提供已确认约束及部分未完成验证 | 是否保留状态转换、失败恢复、跨模块边界、风险与证据缺口；精简后仍可实施和验收 |

四类文档在适用样例中覆盖，不对每种复杂度机械生成完整套件。输入中设置一个已知未验证项和一个需要查明或保留为未知的事实，用于检查状态真实性及防止猜测填充。

## 如何保证对比可信

1. **先固定输入：** 保存用户请求、已有文档、代码或事实材料，以及独立的必要事实与验收清单；生成端不读取评判结论或参考答案。
2. **记录基线：** 使用实施前的规则版本，记录完整提交或内容摘要。当前参考提交为 `52c8c70c08dda1fd06c3c0a3e51faa0673128a2b`；若实施前仓库已变化，应记录实际采用的基线。
3. **仅替换候选规则：** 两组使用相同输入、可用工具和生成任务；使用相同模型与可配置参数，并记录宿主和会话条件。不能控制的差异明确列为限制。
4. **保留原始输出：** 不把人工润色后的文档当候选首次输出；修复和重跑标明版本，保留导致修复的失败证据。
5. **分别判断：** 先检查事实和工程契约，再让读者寻找关键答案；最后比较重复、跳转、裁剪与阅读感受。只统计字数不能代替验收。

一次对照只能支持这些样例的结论。若两组表现接近、输出波动明显或出现失败，只补充能澄清问题的相关复测，不制造无必要的大规模评测。

## 检查与完成条件

- **静态检查：** 实施后运行 `./tests/validate_skill.sh`，核对相对链接、格式和必要契约。测试断言应保护工程行为，不能仅因模板排版变化而保留冗余；格式通过不代表更易读。
- **事实检查：** 对照输入清单逐项核对必要事实、REQ/AC、约束、决策、状态与证据引用。任一关键遗漏或虚构均需修正。
- **阅读检查：** 对每类文档提出与职责匹配的问题，记录答案所在位置、缺失信息及不必要跳转；用户判断是否更容易理解和使用。
- **维护检查：** 对已有文档做一次局部更新，检查无关内容、历史结论和其他事实所有者没有被顺带改写。

T5 完成前，三种复杂度的适用检查均须有实际记录，四类文档均须覆盖，用户须给出阅读体验反馈。尚未实施、仅静态检查通过、或尚无用户反馈时，分别保留对应状态。

结果记录至少包含场景、输入与规则版本、原始输出位置、各项判断、用户反馈和限制。沿用仓库已有测试结果位置；日志按需保存，不新增成功日志目录或第二套验收台账。
