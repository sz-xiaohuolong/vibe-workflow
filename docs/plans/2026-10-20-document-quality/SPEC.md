# 文档质量优化需求分析

| 范围 | 已确认的目标 | 边界与验收 |
|---|---|---|
| Vibe Workflow 工程文档 | 帮助正在 vibe coding 的使用者快速理解重点、判断方案、推进项目 | 首批覆盖需求分析、方案设计、实施计划、进度四类文档 |
| 写作质量 | 先保证看懂和可判断，再减少冗余、统一形式 | 准确性和必要信息完整性是底线 |
| 验收 | 相同输入下比较优化前后的实际输出 | 三种复杂度，最终阅读体验由用户判断；见下方验收要求 |

需求版本：1；状态：已冻结（FROZEN）；确认日期：2026-10-20。依据为本次 grilling 对话中用户对 Q1–Q14 的确认。本文件是此次优化的需求基线，不另建重复的需求简报。

## 目标与范围

主要读者是正在 vibe coding 的用户本人。文档应让用户理解主要方案及其影响，不要求逐项核对函数、类名或实现细节。必要术语首次出现时结合当前项目解释。

首批优化 `SPEC`、`PROPOSED_DESIGN`、`IMPLEMENTATION_PLAN`、`PROGRESS` 的生成与维护。四类是试点范围，不意味着每个任务都必须生成四份文件；继续遵守现有任务分级和文档预算。

用户已于 2026-10-20 确认需求和方案，并要求开始实施；同时将文档中文名称确定为“需求分析”和“方案设计”，文件名沿用原有约定。实际完成情况见进度记录。

## 需求与验收条件

### REQ-01：读者能迅速找到重点

文档开头交代用途与核心结论，相关风险、未决问题和需要用户判断的事项容易定位。正文先解释方案、理由和影响，必要实现细节放在后续章节或已有权威文档中。

**AC-01：** 对适用文档，读者仅靠文档及其明确引用即可回答“要做什么、为何这样做、关键边界是什么、现在需要判断或执行什么”。需求文档提供验收入口，进度文档提供下一步；不机械给所有文档添加同一组字段。失败、阻塞和未验证事实不能被隐藏到附录。

### REQ-02：规范明确且能够照着执行

规范包含通用写法、各类文档骨架、章节裁剪条件，以及合格示例和反例。通用写法覆盖中文表达、标题层级、术语和表格、图示的适用情形。

**AC-02：** 四类文档均能查到用途、必要信息、可选内容及其触发条件，并有可参考的正例与反例。不能只写“必要时补充”而不说明判断依据；普通任务无需额外安装或手动调用写作 Skill。

### REQ-03：内容随任务实际需要增减

简单任务可省略不适用章节；复杂任务保留理解、实施和验收所需的细节。不为填满模板编造内容，也不通过大量拆文件来缩短正文。

**AC-03：** 简单样例不产生空章节、重复视图或无必要的新文件；多步骤流程、复杂状态及跨系统验收等样例保留相应说明。裁剪不能遗漏已知约束、异常行为或验收条件；是否裁剪由内容和风险决定，不以文件数或统一字数上限决定。

### REQ-04：保留事实与工程契约

同一事实由原有职责文档维护，其余位置使用摘要导航或引用。优化表达时保留需求与验收编号、关键约束、决策依据、验证证据和必要交接信息。

**AC-04：** 对照输入核验，输出没有无依据的技术事实、遗漏的关键要求或失效引用；待实施方案、已实现待验证、已验证等状态没有混淆。未知事项明确标注，不猜测补齐；未经验证不改成成功。

### REQ-05：写作与自检融入现有流程

通用原则内置于 Vibe Workflow，详细规范在相关文档任务中按需读取。Agent 自行修正结构和表达问题，不新增逐篇审批或固定的专业技能调用链。

**AC-05：** 普通写作无需用户提醒即可应用规则；小更新检查变更部分及受影响引用，重要新建或实质修改检查整体。只有涉及需求、方案取舍或无法自行查明的必要事实时才询问用户，已有授权不重复确认。

### REQ-06：渐进更新现有文档

新建文档直接应用规范；旧文档在相关任务触及时整理，只修改影响本次工作或理解的部分。

**AC-06：** 局部更新样例保留无关段落和历史事实；不全库重写、不改写已封存文档，也不因统一风格改变已确认需求或技术决策的含义。

### REQ-07：以实际输出验证效果

用相同输入比较现有规则和候选规则在简单、中等、复杂任务上的输出。检查重点定位、事实完整性、重复内容、文件跳转及裁剪效果。

**AC-07：** 保留三种复杂度的输入、基线与候选版本、原始输出和逐项对比结论；四类文档在适用场景中均有覆盖。客观缺陷修正后由用户判断阅读体验。字数仅作辅助记录，不设统一压缩比例；无实际输出或用户反馈时不宣称效果已验证。

## 不在本次试点范围内

- 全场景 LLM 写作规范，以及 README、教程、使用指南等对外文档的写作改造。
- `TECH_DESIGN` 等其余文档类型的模板改造；试点有效后再考虑扩展。
- 新增文档审批阶段、替换七阶段流程、降低原有风险或发布要求。
- 整套安装外部 Skills、付费评测、批量迁移历史项目、提交或发布版本。
