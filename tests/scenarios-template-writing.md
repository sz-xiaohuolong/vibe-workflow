# 标准文档模板执行场景

本轮使用已批准的真实模板改造任务检查写作结果，并使用既有本地样例检查旧需求入口兼容。历史文档质量夹具及输出保留原样，不将其虚构业务或证据称为真实项目测试。

## TW-01 本仓库真实任务的五份文档

### 参与者输入

使用当前 vibe-workflow Skill，为本仓库的“标准文档模板与 PRD 命名优化”编写需求概要、PRD、方案设计、当前技术设计和实施计划。用户已批准以下范围：

- 核心是让 Agent 有可直接填写的规范模板；五模板包括 PROJECT_BRIEF、PRD、PROPOSED_DESIGN、TECH_DESIGN、IMPLEMENTATION_PLAN。
- PRD 按背景、目标、用户、功能优先级、详细规格与验收、交互、约束边界、埋点、待决风险九章组织；保留 BRIEF 分工，前三章有独立摘要后再精确引用概要。
- 新默认名称为 PRD，旧 SPEC 沿用原入口；既有 REQ/AC 和机器状态保持。
- 方案写目标和理由，当前技术设计写已实现且经核验的事实；任务写交付、文件、步骤、验证预期与恢复依据。
- 专业内容按适用条件展开，不照搬示例数字，不默认数据库、缓存或新能力；进度和实际证据由对应记录维护。
- 同步活跃引用、指南、示例、校验，保留历史输出；用户授权完成后提交并更新当前远程分支。

提供只读的本仓库文件快照和当前 Skill。输出写入独立目录，仅编写这五份文档；不修改源码、安装、联网、提交或发布，不运行或声称已运行检查。依据实际文件说明架构，检查仅列为计划；不读取评估依据或此前生成输出。

### 评估依据

- 五份文档按模板实际填写，标准结构和适用契约展开，不能只交摘要或保留填空说明。
- BRIEF 与 PRD 有概要和明细分工，PRD 可独立理解且 REQ/AC 可追踪；无自定产品范围或量化承诺。
- 本任务是 Skill 的 Markdown 模板优化，无业务 UI、数据库或 HTTP 服务；不适用内容正确裁剪，当前结构来自真实文件。
- 方案与当前事实区分；计划有真实文件映射、依赖、步骤、检查预期和恢复依据，实际测试及推送结果不被虚构。
- 输出是本仓库真实任务的文档样例，仅验证生成行为；人类阅读体验尚待用户判断。

### 参与者输入

参与者只获得该输入、隔离工作区和只读 Skill，不获得评估依据与历史结果。

### 评估依据

- 使用并保留 R2 的既有 SPEC.md 需求入口；不新增 PRD.md、第二套地图或迁移历史。
- R1 封存文件、人工说明、源码和测试不被改写，原有 REQ/AC 不重编号。
- 只把实际检查覆盖的 TASK-020 / AC-002 写成已验证；TASK-021 / AC-003 继续未完成、未验证，R2 不因局部通过变为整体完成。
- 既有计划中的运行状态改为进度或验证记录链接，计划不再复制实际完成状态；保留原任务与依赖。
- 当前版本与地图若冲突，应依据源码、计划、进度核实更新；测试结果与证据范围明确，不提交、不推送。

## 记录与边界

独立参与者完成后，主执行者阅读文档、差异与实际运行结果，逐项核对后再记录结论。每例一次生成只支持此次可观察结果，不是稳定性统计；静态检查与人工阅读体验分别记录。
