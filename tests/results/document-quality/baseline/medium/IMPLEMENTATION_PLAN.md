## 任务交接契约

### TASK-020：查询过滤纯函数

- 目标：把现有记录和查询转换为符合需求的展示结果。
- 关联：REQ-001 / AC-001～AC-003；SEAM-001。
- 依赖：已加载的内存记录及冻结的验收条件。
- 允许修改范围：既有过滤纯函数及其相关测试；实际路径由开发时定位。
- 范围外：页面接入、存储改动、网络搜索及新依赖。
- 关键契约：查询先去首尾空白；英文大小写不影响匹配；空查询返回全部记录；过滤不写入源列表、不排序。
- 计划检查：核对既有测试输入与断言；补齐首尾空白非空查询、清空语义、记录内容和数量不变、相对顺序等未被现有摘要证明的检查。仅在实际覆盖不足时补测，不因写文档重跑已知有效结果。
- 预期输出：纯函数、相关测试与可追溯结果；现有实现和证据状态见进度文档。
- 恢复依据：保留接入前既有列表及原始数据路径，尚无已验证提交号。

### TASK-021：接入查询框与列表展示

- 目标：在既有列表组件中完成输入、过滤结果、无匹配提示和清空恢复。
- 关联：REQ-001 / AC-001～AC-003；SEAM-001、SEAM-002。
- 依赖：TASK-020 的既有实现；开始接入时核对函数签名与其实际测试范围。
- 允许修改范围：既有列表组件、必要的局部查询状态与相关组件检查；不预设不存在的文件名或框架。
- 范围外：云搜索、正文搜索、持久化历史、存储格式及权限变化。
- 关键上下文：所有记录已在内存；当前没有查询框；复用现有列表和过滤函数，不另建搜索数据源。
- 实施顺序：定位组件与过滤函数 → 绑定本地查询输入 → 让列表消费派生结果 → 接入无匹配提示与清空操作。
- 验证：输入大小写不同的英文、首尾空白查询、空白查询和无匹配查询；检查提示与列表；优先检查中文输入法组合输入和清空操作。
- 影响路径：查询输入为状态写入入口，过滤函数读取查询与原始列表，既有列表消费结果；清空复用查询更新路径恢复展示。
- 未受影响边界：设计不涉及服务器、数据库或权限；这是范围判断，尚未通过真实代码差异核验。
- 预期输出：可操作的查询界面、对应局部检查记录及需继续验收的缺口。
- 恢复依据：撤回本任务局部接入，恢复既有列表直接展示原始记录的方式。

### TASK-022：完成相关验收并记录结果

- 目标：在接入后的真实页面核对全部 AC，补齐局部单测未证明的交互和数据不变项。
- 关联：REQ-001 / AC-001～AC-003；SEAM-001、SEAM-002。
- 依赖：TASK-021 完成且页面可运行。
- 允许修改范围：相关测试与 PROGRESS 的任务、证据记录；发现实现缺陷时回到对应任务修复。
- 检查步骤：记录初始完整列表 → 查询英文大小写及首尾空白 → 输入空白查询 → 输入无匹配查询 → 使用中文输入法完成组合输入 → 清空 → 核对完整列表立即恢复及记录内容、数量、顺序未变。
- 预期输出：每项检查的输入、实际结果、时间、执行环境与对应代码版本或内容摘要；失败和未运行项明确保留，不以计划代替证据。
- 执行命令：真实项目未提供框架和测试入口，开发时沿用实际命令并记录；当前不编造可运行命令。
- 恢复依据：出现接入回归时恢复既有列表展示，保留失败步骤和相关差异后修复。

## 集成与审查关卡

1. 先核对 TASK-020 与页面使用方式，再完成 TASK-021，最后在同一接入结果上执行 TASK-022。
2. 针对性审查确认原始列表未被写入或排序、提示文案准确、输入和清空使用同一过滤路径、未扩大范围或引入依赖。
3. 仅当 AC-001～AC-003 均有对应实际证据且无阻断问题，才记录功能验收完成；现有 E-01 不足以支持该结论。
4. 记录结果后同步 PROGRESS；不创建 Release 验证套件、额外决策台账或发布任务。
