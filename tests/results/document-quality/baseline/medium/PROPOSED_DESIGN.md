# 方案设计：本地录音列表搜索

## 方案控制

- 适用范围：REQ-001 / AC-001～AC-003，见 [需求分析](SPEC.md)。
- 方案状态：`APPROVED`，依据为 [INPUT.json](INPUT.json) 中已确认的 `chosen_direction`；表示方向已确认，整体实现尚未完成。
- 发布边界：有界功能，无正式 Release。
- 维护日期：2026-10-20。
- 决策依据：用户已确认范围及实现方向，普通内部实现可自主决定；不要求新增独立决策文件。

## 目标与约束

在既有列表组件增加查询输入和纯过滤逻辑，复用现有列表展示搜索结果。仅处理内存中的标题匹配，不增加依赖、网络请求、数据库变化或权限变化；云搜索、正文搜索、持久化搜索历史及存储格式修改均不在范围内。

## 当前事实与目标结构

| 部分 | 已知当前事实 | 目标方案 |
|---|---|---|
| 列表 | 客户端已有组件展示录音，全部记录已加载到内存 | 继续复用既有列表组件及原始记录 |
| 查询输入 | 当前页面没有查询框 | 在列表组件加入本地查询状态与输入控件 |
| 过滤逻辑 | TASK-020 纯函数已实现 | 页面复用该函数，按查询派生展示记录 |
| 页面接入 | TASK-021 尚未开始 | 连接输入、过滤结果、无匹配提示和清空操作 |

以上当前事实来自输入夹具；本次文档维护未读取或核验真实代码。具体文件路径、组件名称及函数签名在开发接入时沿用项目实际结构，不预设框架。

### 数据流与内部契约

```text
既有内存录音列表 ─┐
                 ├→ 既有过滤纯函数 → 派生展示结果 → 既有列表组件
查询输入状态 ────┘                         └→ 无匹配提示
清空操作 → 查询状态为空 → 完整列表
```

1. 原始录音列表作为只读输入；查询状态仅供当前页面使用，不持久化。
2. 过滤逻辑统一处理去除查询首尾空白、英文大小写和空查询，页面避免另写一套匹配规则。
3. 过滤结果引用既有记录，保留其原始相对顺序，不写回或替换原始数据源。
4. 清空沿用同一查询更新路径，立即得到完整列表；不引入防抖等待。
5. 非空查询无匹配时显示规定提示。输入绑定沿用组件现有机制；中文输入法组合事件与清空的实际行为由页面交互检查确认。

### 方案合理性与取舍

所需数据已在内存，搜索范围仅为标题，本地纯函数配合现有组件可直接覆盖需求。新增服务器搜索、搜索索引或新依赖会扩大当前边界，缺少采用依据。先沿用当前简单方案，真实数据规模有测量结果后再判断是否需要优化；目前不设容量或性能承诺。

## 失败与恢复

| 潜在问题 | 检查与恢复方式 |
|---|---|
| 过滤错误或搜索改变原始数据 | 核对 AC 与纯函数行为；保护原始列表，修复受影响过滤逻辑后重验对应条件 |
| 组合输入或清空使页面展示失配 | 用实际输入法检查事件与查询状态；调整局部绑定并复验清空恢复 |
| 页面接入影响既有列表展示 | 撤回查询输入与过滤接入，恢复既有列表组件直接展示原始列表的路径 |

搜索是本地只读派生计算，不需要网络重试或写入幂等方案。恢复依据为既有列表组件；输入未提供已验证稳定提交，不能指定提交号或声称回退已验证。
