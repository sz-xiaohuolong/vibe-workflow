## 任务交接契约

### TASK-030 — 隔离 API 探针（既有记录）

- 状态与证据：见 [PROGRESS.md](PROGRESS.md) 的任务和 `E-02` 记录；不安排本次重跑。
- 可用输出：API 接受取消和幂等键的可行性输入；不得据此跳过正式集成、幂等结果或竞态验证。

### TASK-031 — 队列状态转换与取消竞态

- 切片：`SLICE-01`；目标：以可控适配器建立唯一状态写入者、FIFO 调度、最多 2 个在途尝试及终态保护。
- 追踪：`REQ-001/AC-001`、`REQ-002/AC-002`；同时建立 `REQ-003`、`REQ-005`、`REQ-006` 的状态边界；`SEAM-001`、`SEAM-002` 及恢复规则相关接缝。
- 依赖 / 就绪：已有冻结规格与 E-02 契约输入，可开始；正式实现 `NOT_STARTED`。
- 允许修改范围：实施时确定的内存队列、私有任务与尝试模型、受控 API 替身及相关状态测试。不得接真实 API、修改页面、API 定义、权限或文件数据。
- 关键上下文：方案中的单一事件顺序、创建序号、稳定幂等键、尝试与实例标识、在途名额只结算一次。
- 先写失败用例：至少 4 项的启动顺序与上限；排队取消零请求；上传取消后成功迟到；成功先到；重复取消 / 结束；取消请求迟滞仍占名额；失败后不自动重试；重复重试不重复调度；旧尝试回调无效；暂停禁止新增请求。
- 跨模块影响：定义后续适配层的启动、取消、结束事件契约，以及后续订阅的快照与版本契约。页面目前不得接入；检查原有本地读取路径没有被改动。
- 交付与检查：队列最小实现、上述确定性状态测试、实际运行命令 / 被测版本 / 结果与失败数；验证状态不提前写成通过。
- 可恢复点：开始前记录本地列表、详情和原文件读取基线；本切片独立于页面，可撤回队列新增部分，保留现有本地路径。

### TASK-032 — API、幂等重试和认证暂停集成

- 切片：`SLICE-02`；目标：用现有适配层替换受控替身，保证所有响应仍经过队列。
- 追踪：`REQ-001/AC-001`、`REQ-002/AC-002`、`REQ-003/AC-003`、`REQ-005/AC-005`；`SEAM-001`、`002`、`003`、`005`。
- 依赖 / 就绪：等待 `TASK-031` 状态测试通过；`NOT_STARTED`。
- 允许修改范围：现有上传适配层的内部接线、队列集成与相关测试；沿用 API、认证与幂等参数，不改变公开契约，不新增持久化或远端清理动作。
- 必须先核对：令牌过期错误如何识别、取消句柄何时报告本地请求结束、同一幂等键重复请求的真实结果。输入未提供具体接口签名，实施前通过现有代码和契约核对。
- 计划检查：取消后迟到成功只结算名额；同键重试返回同一远端资源；普通失败无自动请求；两个在途和一个排队时过期全部暂停；登录后等待无请求，手动继续才恢复；再次过期；取消与恢复不得超过 2 个在途请求。
- 跨模块影响：适配层上报结果，队列唯一写状态；登录事件进入队列，不由页面重发上传。检查权限范围、文件格式和原有认证机制未改变。
- 交付与检查：真实 API 集成证据及受控竞态补充证据，记录键、脱敏资源标识、请求时间序列和原文件校验；真实环境缺失时明确缺口，不能用 Mock 替代远端幂等结论。
- 可恢复点：保留 TASK-031 已验证状态契约，撤回 API 接线并停止新增请求，现有本地路径保持可用；不宣称可撤销远端已处理请求。

### TASK-033 — 状态广播、双页面订阅与生命周期

- 切片：`SLICE-03`；目标：两个页面只读取同一队列快照并发送用户命令，页面切换不重建任务。
- 追踪：`REQ-004/AC-004`、`REQ-006/AC-006`，联合取消、重试、认证展示；`SEAM-004`、`SEAM-006` 及相关接缝。
- 依赖 / 就绪：等待 `TASK-032` 集成闭环；`NOT_STARTED`。
- 允许修改范围：私有订阅协议、列表和详情接线、登录提示与继续入口、生命周期测试；不得修改本地文件格式、权限或增加任务恢复存储。
- 计划检查：原子登记与当前快照；版本拒绝旧通知；两页同任务状态；从任一页面取消 / 重试在另一页反映；反复挂载解除订阅无重复请求；订阅建立期间到达终态不漏更新；页面卸载不取消任务。
- 生命周期检查：不同任务状态下重启，旧队列为空且无自动请求；读取原文件并比对内容；验证原有本地列表和详情路径。
- 跨模块影响：队列写入 → 版本化广播 → 两页面读取 → 用户命令回队列；登录状态由既有机制提供。检查现有本地读取和文件保留路径未受影响。
- 交付与检查：接线与订阅测试结果、生命周期结果及真实页面验收所需运行入口。界面行为最终由 `TASK-035` 真实运行核验。
- 可恢复点：撤回新上传入口和订阅接线、恢复原页面读取路径，解除新订阅并停止队列新请求；保留全部原文件。

- 依赖 / 状态：相关实现及局部检查通过后进行；`NOT_STARTED`。
- 追踪与重点：全部 REQ / AC；重点审查取消线性化、名额结算、幂等键生命周期、认证闸门、订阅漏更新及文件写入风险。
- 允许修改范围：审查记录和本轮文档中的相关状态；实现修复返回对应任务处理，不在审查中悄悄扩大范围。
- 交付：被审查版本、范围、发现与处理结果；阻断问题未解决则不得进入系统验收。恢复沿用对应切片稳定点。

- 目标：逐项完成 `AC-001` 至 `AC-006`，验证两个界面、真实 API、重启和原文件保留的组合行为。
- 依赖 / 状态：等待 `TASK-034` 无阻断问题；`NOT_STARTED`。
- 允许修改范围：验收记录和相关文档；发现缺陷返回所属实现任务，不自动提交或发布。
- 检查入口：逐条执行 [SPEC.md](SPEC.md) 验收索引，组合有效单元 / 集成证据；真实运行列表 ↔ 详情、取消迟到响应、手动重试、过期 → 登录 → 手动继续和重启。Mock 只能补充可控时序，不能代替真实界面和远端结果。
- 交付证据：每项 AC 的被测版本、环境、步骤、预期 / 实际、结果、证据指针与限制；无证据的保持未验证。复核切片撤回后本地读取及原文件保留。

## 交付门禁与停止点

每个任务交接需包含实际变更范围、被测版本、适用检查结果、剩余风险和可恢复点。局部测试通过仅推进依赖任务；全部适用 AC 有可取回证据、且无阻断审查问题，才可判断 R3 是否达到 `VERIFIED`。真实环境缺失、契约不符或失败保留原状态并记录缺口。

同类失败连续三次、并发 / 认证假设失效或连锁回归时停止局部试错，记录最小调试快照与当前可恢复点，调查根因后更新计划。扩大冻结边界时先提出变更。
