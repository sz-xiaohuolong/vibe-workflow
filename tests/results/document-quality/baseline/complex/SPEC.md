## 产品行为与验收标准

### REQ-001 — 有序排队与并发上限

- 使用者在现有本地文件路径发起上传后，任务进入排队；在可上传且有空闲名额时，按任务创建顺序启动。
- 同一时刻最多有 2 个任务上传。较早创建且仍可调度的任务先启动；完成顺序可因网络而不同。
- 上传完成显示成功；网络、服务端或本地读取失败显示失败。释放名额后，可继续启动下一项。
- AC-001：建立至少 4 个任务，观察前两个进入上传中，其余排队；任一上传结束后，下一项按创建顺序启动。所有可观察时点的在途上传数不超过 2。
- 错误与边界：慢请求不阻塞另一名额；失败不得自动发起第二次请求；取消或暂停中的底层请求尚未结束时，仍须遵守并发上限。测试入口：`SEAM-001`。

### REQ-002 — 取消与迟到响应

- 排队、上传中任务均可由用户取消，操作结果在任务状态中反映为已取消；本地原文件保留。
- 排队任务取消后不得再开始上传；上传中任务取消时调用已有上传能力执行取消。
- 已取消任务不会被迟到成功、失败或进度回调改写为其他结果；重复取消保持结果稳定。
- AC-002：分别取消排队与上传中任务；验证原文件仍可从既有本地路径读取。向已取消任务注入迟到成功，列表和详情仍显示已取消；排队取消的任务没有上传请求。
- 错误与边界：取消与成功竞争时，以后台队列实际接受事件的先后为准；先接受取消则保持已取消，先接受成功则任务已经完成，后续取消不再改变该终态。取消失败或取消确认迟到不得恢复上传状态。测试入口：`SEAM-002`。

### REQ-003 — 失败后手动重试

- 失败后保留任务与失败结果，等待用户明确点击重试。等待、切换页面和网络恢复均不自动重试。
- 对同一个失败任务重试，复用首次上传的幂等键，避免因重试重复创建远端资源。任务身份和关联本地文件保持一致。
- 重试后重新参与排队及并发约束；已有上传仍可继续，重试不会抢占它们。
- AC-003：模拟服务端已处理但客户端未收到成功的失败场景；等待和切换页面均不新增请求。手动重试后捕获到相同幂等键，真实接口集成验证远端只有同一个资源；连续点击重试不产生多个并发尝试。
- 错误与边界：重试仍失败时回到失败并等待下一次手动重试。前次尝试迟到的回调不得覆盖当前尝试。测试入口：`SEAM-003`。

### REQ-004 — 列表与详情共享状态

- 后台队列是任务状态的唯一写入者。列表与详情订阅同一任务记录，发出用户命令后由队列改变状态并广播。
- 切换页面、进入详情或返回列表不重建任务，不重新上传。新订阅取得当前快照，再跟随后续变化。
- AC-004：任务上传期间往返列表与详情；任务标识、状态和结果保持一致，请求计数不增加。分别从两处发起取消、重试，观察另一处同步到队列接受后的结果。
- 错误与边界：页面卸载仅解除自身订阅；不得取消后台任务。订阅建立恰逢状态变化时不能漏掉最终结果，延迟通知不能覆盖较新的状态。测试入口：`SEAM-004`。

### REQ-005 — 令牌过期与手动继续

- 检测到令牌过期后暂停上传，停止启动待上传任务，并显示登录提示。暂停不删除本地文件，不按普通网络错误自动重试。
- 用户重新登录后仍保持暂停，只有手动继续后才恢复调度；仍适用顺序、并发和幂等性约束。
- AC-005：两个任务上传、另有任务排队时触发令牌过期，观察暂停与登录提示，且不再启动上传。重新登录后等待仍不新增请求；手动继续后才恢复，未结束的旧尝试不得导致额外并发或旧状态回写。
- 错误与边界：登录失败、再次过期时继续暂停并提示；用户尚未登录时点击继续不能发起上传。已完成或已取消任务不因登录而重新入队。测试入口：`SEAM-005`。

### REQ-006 — 非持久化队列与本地文件保留

- 队列与任务状态仅存在于本次运行期间；应用重启后不恢复旧任务，也不自动恢复旧上传。
- 成功、失败、取消、暂停、手动重试以及重启均不删除、移动或修改本地原文件。
- AC-006：在存在排队、上传中、失败、已取消任务时重启，观察旧队列为空、无自动恢复请求；检查原文件内容及既有列表、详情读取路径仍可用。
- 错误与边界：重启造成旧任务状态消失不代表远端操作已撤销。跨重启的新任务不属于同一任务的手动重试，不追加跨重启去重承诺。测试入口：`SEAM-006`。

## 用户流程

```text
从本地文件发起上传 → 排队 → 上传中 → 成功
                                  └→ 失败 → 用户手动重试 → 排队
排队 / 上传中 → 用户取消 → 已取消；本地文件保留
上传中 / 待调度 → 令牌过期 → 暂停并提示登录
                            → 重新登录 → 仍暂停 → 用户手动继续 → 排队与上传
列表 ↔ 详情：读取同一后台任务，页面切换不改变任务生命周期
应用重启 → 丢弃旧内存队列 → 保留现有本地文件路径
```

## 可观察状态转换

| 当前状态 | 事件或条件 | 结果状态 | 用户可见结果 |
|---|---|---|---|
| 无任务 | 发起上传 | 排队 | 出现任务记录 |
| 排队 | 顺序轮到且有名额、认证可用、未暂停 | 上传中 | 两个界面可读到相同状态 |
| 上传中 | 当前有效尝试成功 | 成功 | 显示成功结果 |
| 上传中 | 普通上传失败 | 失败 | 显示失败和手动重试入口 |
| 排队 / 上传中 | 取消被接受 | 已取消 | 原文件保留 |
| 已取消 | 任何迟到响应、重复取消 | 已取消 | 终态保持稳定 |
| 失败 | 手动重试被接受 | 排队 | 复用同一任务的幂等键 |
| 非终态任务 | 令牌过期 | 暂停 | 登录提示，停止上传调度 |
| 暂停 | 登录成功但未手动继续 | 暂停 | 可继续提示，不自动上传 |
| 暂停 | 已登录且手动继续 | 排队 | 恢复后仍受创建顺序和并发约束 |
| 任意内存任务 | 应用重启 | 无旧任务 | 本地文件仍存在 |

暂停是认证阻断时的可见状态；具体状态存储与调度方式见方案设计。失败任务仍须通过手动重试恢复，登录后继续不替代失败重试。

## 非目标与适用限制

本阶段不做断点续传、自动重试、任务队列持久化、新增上传 API 或权限范围修改；不改变本地文件格式。

既有上传 API 已确认支持取消和幂等键，但服务端是否立即回收取消任务占用的带宽未知。因此“已取消”表示本地任务终止及拒绝迟到回写，不承诺立即释放远端带宽、删除已生成的远端资源或跨重启撤销远端操作。
