# 需求分析 — R3 后台上传

| 冻结范围 | 关键边界 | 验收入口 |
|---|---|---|
| 后台队列、取消与手动恢复、列表和详情同步 | 本地原文件始终保留；不承诺取消后立即释放远端资源 | 下方 AC-001～AC-006 与“验收接缝” |

## 需求基线

本需求分析定义 R3 应达到的产品行为，供方案、实施和验收引用。来源为 [INPUT.json](INPUT.json) 的已确认事实；需求版本为 **1 / FROZEN**。云端契约、权限和产品边界已确认，无阻塞产品问题，无需重复批准。

既有上传 API 支持取消和幂等键，最大并发为 2。本阶段不改变上传 API、权限范围或本地文件格式，不包括断点续传、自动重试、队列持久化和新增上传 API。

## 产品行为与验收条件

### REQ-001 — 按创建顺序调度，最多并发两个任务

用户创建上传任务后，任务进入排队；后台队列从可调度任务中按创建先后启动任务。同一时刻最多两个上传尝试占用本地执行槽位；普通完成路径为排队 → 上传中 → 成功或失败。页面切换不改变创建顺序。

**AC-001：** 依次创建 A、B、C，阻止上传响应返回；观察到仅 A、B 启动，C 保持排队。使一个请求结束后，C 才启动；全部调度过程的执行槽位占用数不超过 2。失败任务不进入可调度集合，直到用户手动重试。

### REQ-002 — 取消立即确定本地终态

排队和上传中的任务都可以取消，取消后本地原文件保留。后台队列接受取消时，把任务置为已取消；该任务后续收到成功、失败或取消回调，均不能改变终态。排队取消不发起上传，上传中取消调用既有 API 的取消能力。

**AC-002：** 分别取消排队和上传中的任务，均显示已取消，且原文件仍可从本地路径使用。对已经取消的任务注入迟到成功响应、失败响应和重复回调，两页均保持已取消。取消后立即创建其他任务，执行槽位占用仍不超过 2。

取消与成功的先后以后台队列接受事件的顺序为准：取消先被接受，则迟到成功无效；成功已经提交为终态时，该任务不再属于可取消的排队或上传任务。取消仅保证本地终态与取消请求，服务端是否立即回收带宽未知，不作为验收承诺。

### REQ-003 — 失败只能手动重试，沿用同一幂等键

普通上传错误使任务进入失败，队列不自动重试。用户手动重试后，同一任务重新具备调度资格，保留原创建顺序及幂等键；重试仍受并发限制。幂等键用于使同一任务的重复请求对应同一远端资源。

**AC-003：** 使任务失败，等待调度和页面切换后确认请求次数未增加；手动重试后才出现下一次请求，任务标识和幂等键保持一致。覆盖“服务端已接受但客户端收到错误”的情况，重试后远端资源数量不增加。旧尝试回调不得覆盖新尝试状态。

此要求针对本次内存队列中同一任务的重试；重启不恢复任务，因此不承诺跨重启恢复幂等键或去重历史任务。

### REQ-004 — 列表与详情读取同一个后台状态

后台队列是任务状态的唯一写入者，并向订阅者广播变化。列表页和详情页仅发送命令、读取快照和订阅状态，不各自创建上传任务或维护另一套可写状态。进入、退出或切换页面不重建任务。

**AC-004：** 为同一任务同时观察列表和详情，依次执行排队、上传、失败、重试、成功及取消；两页最终呈现同一任务标识、状态和错误信息。离开页面后上传继续；返回时先读到最新快照，订阅期间无状态倒退或重复任务。页面切换不增加上传请求。

### REQ-005 — 令牌过期暂停，登录后手动继续

令牌过期时暂停上传并显示登录提示。队列停止启动新请求，并暂停受影响的在途工作；重新登录本身不恢复上传，须由用户手动继续。手动继续沿用原任务及幂等键，保持创建顺序和并发约束。已经失败的任务仍需单独手动重试，不能被“继续”自动重试。

**AC-005：** 同时保留上传中、排队和失败任务，注入令牌过期事件；观察暂停提示和登录入口，没有新增上传请求。在暂停前后注入旧请求回调，不能悄然恢复已取消任务或覆盖恢复后的任务。重新登录后仍不启动请求；用户手动继续后，仅恢复被暂停的工作和原排队任务，失败任务保持失败。两页一致展示暂停及恢复结果。

### REQ-006 — 队列仅存于内存，原文件始终保留

应用进程重启后不恢复队列，不重建或自动恢复此前的上传任务。任务成功、失败、取消、暂停及重启均不删除或改写本地原文件。

**AC-006：** 在排队、上传中、失败和取消状态下分别重启应用，重启后没有旧队列或自动启动的旧请求；既有本地列表和详情仍能访问原文件。比较操作前后的文件内容，确认没有删除或格式改变。

## 状态与恢复顺序

下表定义产品可见的转换限制；暂停作为队列调度控制，与单个任务状态分开表达，技术细节见 [方案设计](PROPOSED_DESIGN.md#取消失败与登录恢复)。

| 当前状态 | 事件与条件 | 可见结果 |
|---|---|---|
| 排队 | 队列可运行、有空槽位、轮到该任务 | 上传中 |
| 排队或上传中 | 队列接受用户取消 | 已取消；本地原文件保留 |
| 上传中 | 当前有效尝试成功或普通失败 | 成功或失败 |
| 失败 | 用户手动重试 | 排队；保留任务标识、创建顺序和幂等键 |
| 排队或上传中 | 令牌过期 | 显示登录暂停；停止调度和受影响上传 |
| 登录暂停 | 重新登录完成 | 等待手动继续，仍不调度 |
| 等待手动继续 | 用户继续且令牌有效 | 恢复可调度工作；失败任务不变 |
| 已取消或成功 | 迟到响应、重复回调或页面切换 | 保持终态；已取消任务不能重试为原任务 |
| 任意内存状态 | 应用进程重启 | 队列不恢复；本地原文件保留 |

正常流程为创建 → 排队 → 上传 → 成功。普通失败只能由手动重试返回队列；令牌过期走登录与手动继续分支；取消后结束该任务，不因登录、重试其他任务或页面切换恢复。

## 验收接缝

以下均为后续应建立的验证入口，不表示已经存在测试或已经通过。

| 接缝 | 从哪里输入 | 观察什么 | 对应验收 |
|---|---|---|---|
| SEAM-01 队列调度与状态 | 通过队列命令创建、取消、重试；用可控制完成顺序的上传替身注入结果 | 启动顺序、占用槽位、终态及迟到回调处理 | AC-001、AC-002、AC-003 |
| SEAM-02 上传适配层 | 记录真实契约调用，控制错误、取消完成和幂等响应 | 取消请求、幂等键复用及同一资源结果 | AC-002、AC-003 |
| SEAM-03 双页面订阅 | 列表与详情同时订阅，切换或重新挂载页面 | 任务标识、状态版本、错误和请求数量一致 | AC-002、AC-004、AC-005 |
| SEAM-04 登录暂停 | 注入过期，完成登录，分别执行继续和失败任务重试 | 暂停提示、调度门禁、恢复集合和旧响应隔离 | AC-003、AC-005 |
| SEAM-05 生命周期与本地文件 | 对有状态任务重启进程，重新进入本地列表和详情 | 旧队列为空、没有自动上传、文件内容与可访问性 | AC-006 |

R3 完成验收需要上述六项 AC 的适用运行证据；既有探针的实际覆盖和剩余缺口由 [进度](PROGRESS.md#证据与覆盖限制) 维护。
