# 方案设计 — R3 后台上传

新增一个独立于页面生命周期的后台队列，作为任务状态唯一写入者；列表和详情共用快照与订阅，上传通过现有 API 适配层执行。这样可以统一取消、失败重试和登录暂停的事件顺序，避免两个页面分别推进同一任务。取消后服务端释放带宽的时机未知，方案只保证可控制的本地行为。

## 方案状态与依据

- 方案状态：`PROPOSED`；目标版本：R3。以下为尚未实现的目标设计，不代表现有架构。
- 产品范围、方向、API 与权限契约已按 [INPUT.json](INPUT.json) 确认；本次在该边界内制定内部实现细节，无新增产品审批。
- 行为依据：[需求分析](SPEC.md) REQ-001～REQ-006；执行顺序见 [实施计划](IMPLEMENTATION_PLAN.md)。
- 当前事实：只有本地文件列表和详情页，尚无正式后台队列。隔离 API 探针的覆盖见 [进度的 E-02](PROGRESS.md#证据与覆盖限制)，不能作为 API 已集成、页面已同步或完整上传已可靠的依据。

## 目标结构与责任

| 组件 | 写入与读取责任 | 选择理由 |
|---|---|---|
| 后台队列 | 唯一接收创建、取消、重试、继续及异步结果的入口；串行提交状态，负责排序和两槽调度 | 把竞态决策集中在一处，页面退出后仍保留任务 |
| 现有上传 API 适配层 | 接收幂等键与取消信号，返回结果或错误；不直接改任务状态 | 复用已确认契约，不新增上传 API |
| 共享订阅入口 | 提供当前快照与变化通知，携带递增状态版本 | 新页面可立即获取最新状态，旧通知可被识别 |
| 列表页与详情页 | 发命令、读快照、订阅；卸载时只退订 | 页面不持有调度器，切换页面不重建任务 |
| 既有登录通道 | 向队列报告令牌失效和重新登录；继续命令来自用户 | 登录完成与恢复上传分开，避免自动恢复 |

页面发命令 → 队列更新状态并广播 → 适配层执行上传 → 结果回到队列校验后提交。API 回调不得绕过队列直接更新页面。

任务在创建时一次性生成任务标识、创建序号和幂等键，并保存原文件引用；另保存状态、当前尝试标识和可见错误。重试复用前三项，生成新的尝试标识。队列只在内存中保存这些信息，不修改原文件格式，不添加队列持久化。

## 排序、并发与异步结果

从符合调度条件的任务中按原创建序号取最早任务；失败任务只有收到手动重试后才重新参与排序，不阻塞后续可运行任务。

每个实际上传尝试独占一个槽位，启动前占用、结束后释放，同一时刻最多 2 个。逻辑取消或暂停可以先确定用户可见状态，但旧请求尚未结束时仍占槽，不能仅因页面显示已取消便发出第三个请求。旧请求的结束回调只释放该尝试的槽位一次，不能释放新尝试的槽位；同一任务也不能在旧尝试尚未结束时启动下一次尝试。

每个回调携带任务标识和尝试标识。队列串行处理命令和结果，先检查任务终态、当前尝试和暂停期间失效标记，再决定是否提交结果；拒绝的旧回调仍可完成其自身槽位清理。状态提交后增加版本并广播，禁止旧事件把状态改回过去版本。

## 取消、失败与登录恢复

### 取消的提交点

接受取消时先提交已取消终态，使当前尝试失效并广播，再对在途请求发取消信号。排队任务直接取消，无需发上传请求。取消 API 成功或失败都不能把已取消改成上传成功或普通失败；取消清理问题单独记录，原文件保留。

如果成功已经先被队列提交，则不再接受对该成功任务的取消。这个确定的事件顺序对应 AC-002，避免两个页面各自判定取消是否成功。

取消信号不等于服务端已经停止传输。当地传输结束后可释放本地槽位，但不能由此声称远端带宽或资源已立即释放；如果取消请求未结束，后续调度可能等待槽位。这是当前契约下优先遵守并发上限的代价。

### 普通失败与手动重试

适配层把普通网络或上传错误交回队列，队列提交失败和错误信息。调度器不轮询或自动重试失败任务。只有用户重试命令能使其重新排队，幂等键不变，新旧尝试以不同标识隔离。

服务端可能已接受一个在客户端表现为失败的请求，因此重试必须复用同一幂等键。API 探针仅证明接口接受该字段；实际“不产生重复资源”仍需在集成验证中检查，不能由字段存在直接推定。

### 登录暂停与继续

队列调度控制分为“可运行”“登录暂停”和“等待用户继续”，不增加持久化任务状态。令牌过期时先关闭调度，广播统一登录提示，使受影响的在途尝试失效并发送取消信号。原排队任务保留；被中断的上传任务回到待调度集合并标示登录暂停，保留原任务、创建顺序和幂等键。这属于暂停后的手动恢复，不把任务标为普通失败后自动重试。

重新登录只切到“等待用户继续”。收到用户继续且令牌有效时才打开调度；旧请求仍占用的槽位须先完成清理。已经失败、已取消或成功的任务不加入恢复集合。暂停期间，原排队任务及被中断任务仍可走取消入口；继续命令不得恢复已取消任务。

令牌过期事件之后到达的旧结果不再提交任务结果；即使远端已完成，后续手动继续也用同一幂等键取得同一远端资源结果。恢复过程中再次过期时重新关闭调度，不能形成连续自动重试。

## 订阅与页面恢复

每次订阅应把当前快照和后续通知接成一个连续版本序列，避免“先取快照、后订阅”之间漏掉状态。两个页面都按任务标识合并新版本，丢弃重复或更旧版本；取消、错误和全局登录暂停都通过同一入口传播。

页面卸载只解除其订阅，不销毁队列或上传。再次进入页面时获取最新快照，再继续收取变化。应用进程重启则创建空队列，不恢复旧任务；本地文件列表和详情仍从原本的数据入口读取原文件。

## 影响、风险与恢复

受影响范围包括新增队列、共享订阅、现有适配层接入、两个页面的任务展示和登录暂停联动。API、权限范围及文件格式的边界保持已确认约束；现有模块的具体代码与兼容性尚未检查，因此本文件不把任何模块标成“已核查无影响”。

| 风险 | 控制与验证重点 | 剩余限制 |
|---|---|---|
| 取消后迟到成功覆盖状态 | 先提交终态，失效当前尝试；测迟到和重复回调 | 不承诺删除已形成的远端资源 |
| 取消或暂停提前放槽造成超并发 | 槽位绑定尝试，等待该尝试结束后释放 | 清理未完成时可能影响后续启动 |
| 重试创建重复资源或旧错误覆盖新结果 | 幂等键不变、尝试标识更新；测服务端已接受但客户端失败 | 跨重启恢复不在范围内 |
| 登录即自动恢复、失败混入恢复集合 | 登录与继续分离；区分暂停工作和普通失败 | 令牌过期和端到端行为均待验证 |
| 两页错过通知或各自创建任务 | 唯一写入者、连续快照订阅、状态版本 | 仍需真实页面运行证据 |

失败时恢复现有本地列表和详情路径，并保留全部原文件。实施前须先确认这两条路径的可恢复检查点；目前没有已验证的完整上传稳定提交，不能声称可回滚到某个“上传已正常”的版本。停用新队列入口后也不得删除原文件，远端残留情况单独核查；恢复后复查本地浏览和文件可访问性。

## 验证方式

| 关联需求 | 计划检查与判定 | 应保留的证据 |
|---|---|---|
| REQ-001、REQ-002 | SEAM-01 控制请求结束顺序，测试取消与成功的两种先后、重复回调及槽位释放 | 状态序列、请求启动顺序、槽位峰值和任务标识 |
| REQ-003 | SEAM-01/02 验证无自动重试、旧尝试隔离、重试键不变及远端不重复 | 调用次数、键一致性与远端资源结果 |
| REQ-004 | SEAM-03 在更新、切页和重挂载交界处观察两页 | 同一任务的页面状态、版本及请求数量 |
| REQ-005 | SEAM-04 覆盖过期、登录、手动继续、再次过期、暂停期间取消 | 调度门禁变化及恢复集合；登录后未自动发请求的记录 |
| REQ-006 | SEAM-05 在不同任务状态重启并返回既有页面 | 空队列、本地文件内容与可访问性记录 |

每项验证需对应实际被测版本和环境；本次仅形成文档，未执行这些检查。结果与证据限制统一维护在 [进度](PROGRESS.md)，不从方案预期推导通过结论。
