# 需求分析 — R3 后台上传

| 冻结范围 | 关键边界 | 验收入口 |
|---|---|---|
| 应用内后台上传队列、取消、手动恢复与列表/详情同步；需求版本 1，`FROZEN` | 并发最多 2；本地原文件始终保留；队列不跨重启恢复 | 下文 AC-001～AC-006 与“验收接缝” |

本需求分析定义 R3 应有的用户行为。可靠性的判断重点是：取消能否抵御迟到响应、失败恢复能否避免重复远端资源，以及页面切换能否保持同一份任务状态。具体实现选择见 [方案设计](PROPOSED_DESIGN.md)。

## 需求基线与边界

- 事实来源：[INPUT.json](INPUT.json) 的 `facts.requirements`、`baseline`、`approved_contract` 与 `non_goals`；Release 为 R3。
- 需求版本为 1，状态为 `FROZEN`。云端契约、权限与产品边界已经确认，直接沿用。
- 既有上传 API 支持取消和幂等键。本阶段不新增上传 API，不修改权限范围或本地文件格式。
- 非目标：断点续传、自动重试、任务队列持久化。后台上传表示任务不依附于列表或详情页面；本需求不增加跨进程恢复能力。
- 服务端是否立即回收取消任务占用的带宽未知；验收不以“取消后立即释放远端资源”为承诺。

## 产品行为与验收条件

### REQ-001 — 按创建顺序排队，并发最多 2

用户创建上传任务后，任务先排队，再进入上传中，最终成功或失败；取消和令牌过期按下文例外处理。处于排队状态的可执行任务按创建顺序获得上传机会。

**AC-001：** 连续创建 A、B、C 三个任务并控制前两个请求不结束，观察到 A、B 上传中、C 排队，上传请求同时在途的数量不超过 2。一个上传请求结束后，C 才获得空位。对更多任务重复观察，启动次序保持创建顺序。

### REQ-002 — 排队和上传中均可取消

用户可取消排队或上传中的任务。取消后本地原文件保留，任务显示为已取消。取消已经被任务系统接受后，迟到的成功响应不能把该任务恢复为成功。

**AC-002：** 分别取消一个排队任务和一个上传中任务：前者不再启动上传，后者接受取消后保持已取消；再注入该上传请求的迟到成功、失败或取消回调，任务仍为已取消，两处页面均展示这一结果，本地原文件仍可读取。若成功已经先被接受，任务已经成功，则不把它当作“上传中取消成功”的案例。

### REQ-003 — 失败后仅手动重试

普通上传失败后显示失败，任务不会自行重新上传。用户手动重试时沿用同一任务的幂等键，以免重复创建远端资源。

**AC-003：** 制造一次普通失败，等待并切换页面，均没有自动重试请求；用户手动重试后才产生下一次请求。记录两次请求的幂等键相同，并在受控 API 集成场景中核对同一键不会生成两个远端资源。仅检查客户端传入相同键不足以证明远端去重。

### REQ-004 — 列表和详情共享同一任务状态

列表页与详情页订阅同一任务状态；只有后台队列能够写入任务状态并广播变化。页面仅展示状态、发出操作意图，不维护另一份可独立推进的任务生命周期。切换页面不重建任务。

**AC-004：** 上传、取消、失败、重试期间交替进入列表与详情，两个页面对同一任务显示一致的最新状态。往返切换页面后，任务标识、已创建任务数量和上传请求数量不因页面挂载增加；详情重新订阅后能读到离开期间发生的状态变化。

### REQ-005 — 令牌过期暂停，登录后手动继续

令牌过期时暂停上传并显示登录提示。重新登录只解除身份条件，用户仍需手动继续；不能借登录成功自动恢复上传。普通失败任务仍遵循 REQ-003，不能被“继续”隐式重试。

**AC-005：** 在有上传中与排队任务时触发令牌过期，观察上传暂停、后续任务不再启动，两处页面均可观察登录提示。重新登录后继续等待，仍不出现新的上传请求；用户手动继续后，暂停的未完成任务才恢复调度。已失败、已取消或已成功任务不因登录或继续操作自动重传。

### REQ-006 — 队列不持久化，本地文件保留

本阶段仅维护内存任务队列，应用重启后不恢复先前任务。本地原文件在成功、失败、取消、令牌过期以及重启后均保留。

**AC-006：** 创建并运行任务后重启应用，先前任务不恢复，也不自动产生上传请求；原有本地文件仍可从既有列表和详情路径读取。分别核对成功、失败和取消路径不会删除或改写原文件。

## 状态与操作顺序

正常路径为“排队 → 上传中 → 成功或失败”。取消为终态；失败只允许用户手动重试。令牌过期形成覆盖未完成任务的暂停条件，重新登录后还需要手动继续。

| 当前状态或条件 | 事件 | 可观察结果 | 关联验收 |
|---|---|---|---|
| 排队，且未暂停、有空位 | 轮到该任务 | 进入上传中 | AC-001 |
| 排队或上传中 | 取消被接受 | 进入已取消，保留原文件 | AC-002 |
| 上传中 | 本次有效上传成功或普通失败 | 进入成功或失败 | AC-001、AC-003 |
| 已取消 | 迟到的上传响应 | 保持已取消 | AC-002 |
| 失败 | 用户手动重试 | 重新排队，沿用幂等键 | AC-003 |
| 未完成任务 | 令牌过期 | 上传暂停，显示登录提示 | AC-005 |
| 因令牌过期暂停 | 重新登录 | 保持暂停，等待手动继续 | AC-005 |
| 已登录、仍暂停 | 用户手动继续 | 未完成任务恢复调度 | AC-005 |
| 成功或已取消 | 后续响应、登录或继续 | 保持终态，不自动重传 | AC-002、AC-005 |
| 任意任务状态 | 应用重启 | 不恢复队列；原文件可读取 | AC-006 |

一次典型失败恢复过程是：任务上传失败 → 用户看到失败 → 页面切换仍显示失败 → 用户选择重试 → 相同任务重新排队 → 使用原幂等键上传。登录过期走单独的暂停与继续流程，不冒充普通失败重试。

## 验收接缝

以下为计划使用的输入与观察位置，不表示检查已经执行。实际证据状态统一记录在 [进度](PROGRESS.md)。

| 接缝 | 输入与控制点 | 观察与判定 | 覆盖 |
|---|---|---|---|
| SEAM-01：队列事件与调度 | 创建任务；控制请求完成顺序；在取消前后释放成功/失败回调 | 状态序列、启动顺序、在途数；取消终态不可被覆盖 | AC-001、AC-002 |
| SEAM-02：API 适配层 | 捕获取消调用与幂等键；注入普通失败、令牌过期；受控服务端去重记录 | 无自动重试、相同键、远端资源数量；暂停后没有新启动 | AC-002、AC-003、AC-005 |
| SEAM-03：列表/详情订阅 | 页面往返、订阅建立前后触发状态变化；从任一页面发出取消或重试 | 两页对同一任务的最新状态一致，任务与请求不因切页增加 | AC-002、AC-003、AC-004、AC-005 |
| SEAM-04：进程与本地文件 | 结束并重启应用；读取既有原文件 | 内存任务不恢复，原文件仍可读取 | AC-006 |
