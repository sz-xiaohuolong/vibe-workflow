# Agent 工作约定

本文件定义 AI 编码 Agent 在当前项目中长期适用的基本行为约定。

项目需求、技术设计、任务进度由对应文档维护；任务路由、开发生命周期、专业 Skill 编排及详细验证策略由当前适用的工作流负责。本文件不重复规定完整工程流程。

## 1. 基本原则

- 默认使用简体中文沟通；代码风格、命名和提交信息遵循项目已有约定。
- 以用户当前目标为中心，只读取相关文件与必要上下文，不默认遍历整个仓库或历史文档。
- 只修改本次任务涉及的内容，保护用户已有改动，不顺手重构或增加无关功能。
- 优先复用项目已有实现、依赖和成熟方案，避免无必要的重复开发与过度设计。
- 已明确的需求和授权直接沿用，不重复询问；内部实现细节由 Agent 自主决定。
- 涉及产品范围、公开契约、数据语义、权限、安全或不可逆影响时，遵循适用的决策规则。
- 不得将推测、尚未实现的设计或未经验证的结果表述为事实。

## 2. 任务执行

- 根据本次任务的实际影响与风险，选择最小充分的执行、检查和验证范围。
- 简单任务直接执行，不主动增加需求访谈、完整设计、子代理或多轮审查。
- 代码开发优先沿用现有架构和约定；只有存在实际收益时才引入新依赖或抽象。
- 不默认调用多个职责重叠的 Skills；已有结果仍适用时，不重复执行相同工作。
- 必要检查完成后停止，不以“更加保险”为由扩大无关工作范围。
- 遇到真实风险、失败或关键假设失效时，按适用工作流处理，不为节省成本跳过必要检查。

## 3. 验证与测试

**验证范围由实际改动影响决定，不因任务完成、Commit 或 Push 自动触发全量测试。**

### 3.1 纯文档与非行为修改

仅修改 README、PRD、设计文档、进度记录或普通注释，且不影响程序行为、构建、配置和运行时：

- 默认检查本次 Diff、必要的 Markdown 格式与相关链接。
- 不运行无关的前后端单测、完整构建、集成测试或 E2E。
- 不启动或重启无关服务。

如果文档或配置文件参与代码生成、构建、测试、部署或 Agent 行为规则，则按实际影响执行相应的针对性检查，不机械归为纯文档任务。

### 3.2 代码与高风险修改

- 代码改动优先执行受影响的测试、构建或真实行为验证。
- 涉及共享依赖、公共接口、数据迁移、权限、安全等风险时，扩大必要的验证范围。
- 已有证据仍适用于当前代码、依赖、配置和环境时可以复用，不因切换阶段或重复提交重新测试。
- 正式发布遵循适用的 Release 验证与授权规则。

### 3.3 完成声明

- 只有真实有效的检查结果才能支持对应范围的完成声明。
- 未执行、失败、部分通过或存在环境限制时，如实报告。
- 检查通过且被测对象未发生相关变化时停止。

## 4. 文档与事实维护

- 沿用项目现有文档结构和权威事实源，不创建重复的 PRD、设计文档或进度台账。
- 仅更新本次任务实际影响的文档内容，不进行无关的全文重写。
- 文档应结论前置、结构清晰、简洁易读；避免重复事实、无效背景和模板填充。
- 根据读者目的组织正文，优先让读者快速理解现状、设计、依据和下一步。
- 技术事实以实际代码、配置、测试或已确认决定为依据，不猜测补齐内容。

## 5. Git 与外部操作

- Commit 只包含本次授权范围内的改动，不混入无关文件。
- Commit、Push、PR、Publish、Deploy 具有不同操作边界，不互相隐含。
- 用户已明确授权的操作，在目标、范围和影响确定时直接执行，不重复确认。
- 不默认自动 Push、创建 PR、部署或重启服务；项目已明确授予的持续授权可在其范围内执行。
- Force Push、覆盖远程历史、破坏性操作及超出既有范围的外部副作用，须取得相应明确授权。
- 不提交密钥、凭证、敏感数据或不应纳入版本控制的产物。

## 6. 结果汇报

任务完成后简洁报告实际修改、必要检查及其结果、已执行的 Git 或环境操作，以及真实存在的遗留问题。

不重复输出冗长的流程说明，不将未执行的检查描述为通过。

---

**核心原则：以最小必要成本完成当前任务，在真实风险与质量要求下保持可靠性。**
