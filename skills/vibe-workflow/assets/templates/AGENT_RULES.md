# Agent 工作约定

本文件规定 AI 编码 Agent 的工作行为与项目边界。
产品需求、技术方案和实施进度由对应项目文档维护，本文件只保留必要入口和约束。

## 1. 基本行为

- 默认使用简体中文沟通；代码与提交信息遵循项目约定和用户明确要求。
- 先查相关项目文档、现有代码和测试。已有资料能回答的问题，不重复询问用户。
- 只修改当前任务涉及的内容，保留用户已有修改，不顺手进行无关重构。
- 优先沿用项目已有模式，不为假设中的未来需求提前建设复杂抽象。
- 如实说明已完成内容、未完成项和阻塞，不承诺未经实际安排的后台交付。

## 2. 规则与事实来源

- 遵循宿主的指令优先级，读取当前修改范围内适用的项目规则。
- 沿用项目已有的文档路径和职责分工，不创建重复的需求、设计或进度文档。
- 产品预期以已确认的需求为依据；当前实现以代码、配置、测试和运行结果核验。
- 发现文档、代码或用户目标不一致时，说明差异并确定需要修正的事实源，不静默猜测。

## 3. 开始与实施任务

- 开始前确认本次目标、修改范围、验收方式及必要的前置依赖。
- 只加载当前任务需要的上下文；跨会话继续任务时，核对已有进度与实际仓库状态。
- 按最小可验证闭环推进，只实现当前任务实际涉及的层和模块。
- 产品范围、公共契约、数据含义、权限或不可逆影响发生变化时，先明确必要决定，再实施。
- 已有明确授权覆盖本次工作时直接沿用；普通内部实现细节由 Agent 自主决定。
- 待确认方案与当前事实分开记录，未实现、未验证的设计不能写成既成事实。

## 4. 完成与验证

- 执行与本次改动相关、且项目要求的检查，验证受影响的行为和风险。
- 完成声明必须有对应的真实证据；未运行、失败、部分通过和环境限制须明确说明。
- 已有结果仍适用于当前代码、配置和环境时可以复用；变化使证据失效时，重验受影响部分。
- 完成后同步受影响的现有文档和进度记录，说明结果、证据、遗留问题及必要的下一步。
- 检查通过且没有新变化时停止，不无依据地扩大测试或修改范围。

## 5. Git 与敏感信息

- 提交只包含本次任务相关修改，不混入无关格式化、重构或用户未授权的改动。
- 仅在明确授权范围内推送远程或发布版本；已有授权不重复申请，不扩大授权目标。
- 不提交真实密钥、凭证、敏感环境配置或未经脱敏的数据。
- 日志、缓存、依赖目录和生成物按项目的版本控制约定处理。
