# 专业技能的编排边界

## 何时读取

准备调用外部技能、处理职责冲突或核对更新兼容性时读取。Tiny 没有实际外部能力需求时无需加载。

## 单一 owner 与调用契约

vibe-workflow 维护范围、事实源、阶段和交付状态；专业技能执行本次委派工作。宿主指令、用户请求和已有明确授权优先，项目规则在适用范围内执行。

在任务上下文明确以下内容，不另建契约文件：

- 目标与冻结输入：实际 diff、必要 REQ/AC 或用户精确请求。
- 允许修改范围与权威输出路径：沿用 Document Map，无文档需要时返回对话结果。
- 副作用：是否允许改代码、提交、安装、外部数据发送或发布；授权只对本次范围有效。
- 验证与预算：检查什么、已有证据能否复用、需要什么输出。
- 停止点：完成当前能力后返回，由唯一 owner 决定下一步。

先看实际注册项，再读对应正文与必要资源。缓存文件不等于已启用。`gstack:qa-only` 等为逻辑名，实际可能是 `gstack-qa-only` 或 `qa-only`；仅限用户调用的入口不可自动选择，技能名不能作为 shell 命令。缺失与调用失败分别说明，不伪装已调用。

若技能强制行为超出本次契约，选择更窄技能或内置必要步骤；不要宣称完整执行却暗中跳过它的必要步骤。它建议的下一技能也须重新核对边界。

## 冲突处理表

| 场景 | 决策 |
|---|---|
| using-superpowers 等启动器要求先运行所有可能相关的流程 | 用户显式指定 vibe-workflow 或项目规则已选它作为编排入口时，按本次路由选择能力；冻结需求不重访谈、Tiny 不扩流程。用户/宿主指令优先；若用户尚未选择编排方式，不声称另一个 skill 会自动服从本 skill，也不修改全局启动钩子。 |
| grilling、brainstorming、office-hours 都想访谈 | 未决产品范围优先 grilling；grill-me 仅用户入口。复用已回答的事实和决定。 |
| Superpowers 7 brainstorming 接到冻结需求 | 不作为技术选型固定前置；技术比较用内置分析及必要评审。显式请求时保留确认输入，只处理缺口；“跳过提问”不替代未决产品决定。 |
| autoplan 与各单项评审重复 | 多维复杂问题选 autoplan，单一问题选对应评审；不再重跑其中已完成的审查，范围变化或新风险才增补。 |
| writing-plans 默认写 docs/superpowers | 输出到既有计划 owner；不能接受既有路径时内置拆解，不建第二套 PRD/PLAN。 |
| SDD、executing-plans 与并行工具竞争 | 复杂 written plan 二选一；SDD 的实现子代理串行。简单计划可直接执行，不因“有计划”强制委派。 |
| using-git-worktrees 默认创建目录 | 仅需隔离并发修改、长期分支或用户要求时使用，优先复用；Tiny 默认原地修改。 |
| TDD 要求文案文档先失败 | 行为改动和 Bug 优先 TDD；无行为变化编辑用 diff、静态或现有检查，不写仅镜像文案的测试。 |
| review、requesting-code-review、deslop 重叠 | 选一个主审查；确有跨模块重复及维护成本时加 deslop，不强造公共抽象。 |
| QA 在 Testing 自动修复提交 | 纯验收用 qa-only/browse/原生测试。qa 需修复及提交行为均获授权，否则只读验收后由 owner 修复；改动后复审重验受影响部分。 |
| verification-before-completion 要重跑有效证据 | 用证据适用性决定是否重验；无法接受预算时用内置 Completion Gate，不声称执行了该技能。 |
| ship 默认开 PR 或接管普通 Git | 同步远程走轻量 Git；个人发布默认原生 Git + 项目命令。只有用户显式要求 PR 才选择相应 ship 流程；不可为技能默认行为创建 PR。分支保护拒绝直推时报告并等待选择。 |
| retro、引导、遥测、外部评审抢占任务 | 只执行本次必要且获授权的行为。可选偏好设置和跨服务审查不作前置；无法分离时降级。 |

## 内置最小协议

- 澄清：先查事实，只问阻塞产品决定；每轮合并无依赖的问题并给建议，有依赖的留待下一轮。范围明确即停止，不穷举假想分支。
- 方案/计划：比较实际有分量的方案；普通内部实现自主选择。只记录目标、范围、依赖和验收必要信息。
- 实现/排障：确认预期、查代码、必要时复现与失败回归测试、修复根因、运行相关检查。
- 审查：核对 diff 与承诺、边界、安全和受影响行为；无实际发现不制造修复。
- 完成：读真实结果，核对输入与覆盖，记录缺口；没有真实环境不声称运行成功。

## 更新后的检查

核对名称、调用限制、资源、输出路径、副作用、后续自动调用和重复验证。外部版本更新不自动改变批准记录。使用代表性场景验证，只报告实际执行过的检查。
